# The data layer

Daily bars, where they come from, and what they are worth.

---

## The short version

> **The free data stack exists to exercise machinery, not to produce
> conclusions.** No delisting returns, no point-in-time restatements, no
> survivorship guarantees of its own, adjustments that are whatever the vendor's
> are. Every number derived from it is a statement about this pipeline. When a
> number from it could be mistaken for a result, it is labelled.

---

## Getting data

```powershell
# One symbol, or many
python scripts/fetch_stooq.py --symbols AAPL MSFT SPY
python scripts/fetch_stooq.py --symbols-file universe.txt --delay 1.5

# What have I got?
python scripts/fetch_stooq.py --status
marketscan.exe --headless --cache-info data/cache/stooq
```

> ### ⚠️ Stooq's CSV endpoint is currently gated
>
> As of 2026-09-17 Stooq answers every request to `/q/d/l/` with **HTTP 200 and
> a JavaScript browser-verification page** rather than CSV. Nothing here
> attempts to defeat that check.
>
> The fetcher detects it and says so by name, rather than reporting "symbol is
> probably unknown" and sending you hunting for a ticker problem that does not
> exist. Everything else in the project works without it: the cache format, the
> feed, the universe, the guard and the identity classifier are all exercised
> against committed synthetic fixtures. What is blocked is **measuring** real
> identity — see [`IDENTITY.md`](IDENTITY.md).
>
> Restoring it means a different source, not this one. The gate is a
> **proof-of-work challenge served unconditionally on a cold request** — a
> deliberate configuration, not an outage, so waiting is not a plan. This project
> does not solve it, and the fact that it would take a dozen lines made no
> difference to that: see [`DATA_POLICY.md`](DATA_POLICY.md), rule one, where the
> Stooq case is the worked example.
>
> Substituting a source is a decision, not a fix. The bar is an API key and
> documented terms; **silence is not consent**. And the constraint that actually
> governs the choice is *delisted coverage* — a vendor carrying only live tickers
> cannot answer the question the price data is wanted for, at any price.

[Stooq](https://stooq.com) publishes end-of-day US equity history as CSV over
plain HTTP. No API key, no account, no paid tier — which is the entire reason
it is the source here. Nothing in this project requires asking anyone for
permission to run it.

The fetcher is **polite by construction**: requests are serialised, spaced by a
configurable delay, retried with exponential backoff, and never repeated for a
symbol already cached. Running it twice makes no network requests the second
time. It saves the manifest after every symbol, so an interrupted fetch resumes
from where it stopped rather than from nothing.

A symbol that cannot be fetched is **logged and recorded as failed**, never
silently skipped. A universe that quietly lost a name produces a backtest that
nothing can tell apart from one where the name was never in the index.

```powershell
# Already have data from somewhere else
python scripts/csv_to_msb.py export.csv --out data/cache/mine --symbol AAPL
```

**Nothing fetched is committed.** `data/cache/` is gitignored. What *is*
committed is small, synthetic and generated by a script:
`data/samples/synthetic_daily_5.csv`, five names over three years.

**No test touches the network.** The fetcher is a script, deliberately, so that
nothing in the test suite can depend on someone else's service being up.

## The cache format

Cached bars are a binary file per symbol, `TICKER.msb`, documented in
[`bar_store.hpp`](../include/marketscan/data/bar_store.hpp).

Twenty years of daily bars across five hundred names is about two and a half
million rows. As CSV that is roughly 150MB of text to parse on every run, and
the parsing is not incidental: turning a decimal string into a double two and a
half million times is most of what a replay costs before a strategy has been
asked anything. The same data as a header and a packed array of fixed-size
records reads in one pass with no parsing at all.

| offset | size | field |
|---|---|---|
| 0 | 4 | magic, `MSB1` |
| 4 | 4 | format version |
| 8 | 8 | record count |
| 16 | 32 | ticker, NUL-padded |
| 48 | 8 | interval in nanoseconds |
| 56 | 8 | reserved |

Then `count` records of 48 bytes: timestamp, open, high, low, close, volume.
Little-endian and IEEE-754, both asserted at compile time rather than assumed —
a file written on one machine and read on a machine that disagreed would not
fail, it would produce prices.

The cost of a binary format is that it is not greppable. `--cache-info` is the
answer to that: the question "what have I actually got" should not require
writing a program.

### What a daily timestamp means

A daily bar covers a session, and a session is not an instant. It is stamped at
the **close** — 16:00 in the exchange's own time zone, converted to UTC through
the same calendar the session boundaries use, so the stamp moves with daylight
saving exactly as the closing bell does. 21:00 UTC in January, 20:00 UTC in
July.

The close, not the open, because that is when the information in the bar
exists. A strategy handed a daily bar stamped at the open could act at 09:30 on
a high, a low and a close that had not happened yet, and would look extremely
clever.

## Replaying it

```powershell
marketscan.exe --headless --daily data/cache/stooq
```

`DailyBarFeed` loads every `.msb` in a directory, merges them into one
timestamp order, and is a **single source** rather than one source per symbol.
That is deliberate: five hundred symbols as five hundred sources would make the
engine's k-way merge scan five hundred slots per event, which over two and a
half million events is a billion comparisons spent deciding what to dispatch.
Merging once costs about 50 bytes a bar — a hundred megabytes for twenty years
of five hundred names — and buys a replay whose per-event cost is a pointer
increment. Measured: 378,000 events across 300 symbols and five years in under
half a second, including reading the files.

If that memory ever becomes the constraint, the answer is a packed
already-sorted bundle streamed from disk, not five hundred sources.

**Quotes are synthesized by default here**, unlike the intraday CSV path. A
daily file has no quotes and never will, so a run without them has nothing for
a market order to cross and fills at the close — which is the optimistic fill
model wearing a disguise. The synthesized spread is 2 basis points around the
close, which is roughly right for a liquid large-cap and wrong for everything
else; it is a single number standing in for a distribution that varies by name,
by size and by minute, and it is there to make the spread non-zero rather than
to be accurate.

**A corrupt or impossible bar fails the run.** Not skipped: a cache with one
bad symbol produces a backtest over a universe that quietly lost a name. A bar
whose high and low do not bracket its open and close is refused at load,
because it would let the fill simulator trade at a price the day never saw and
nothing downstream could detect it.

## What this is missing

Named, because a gap you cannot see is worse than one you can.

| | |
|---|---|
| **Delisting returns** | The single biggest one. A company that goes to zero simply stops having bars. See [`IDENTITY.md`](IDENTITY.md) for what the universe layer does about it, and why that is still optimistic. |
| **Point-in-time restatements** | Prices are as they are today, including every adjustment made since. A backtest sees a split-adjusted history nobody had at the time. |
| **Corporate actions** | No spin-offs, no mergers, no rights issues. A name that spun off half its business shows a price drop that looks like a loss. |
| **Halts and suspensions** | A halted day is an absent bar, indistinguishable from a holiday. |
| **Multiple share classes** | Stooq's ticker space flattens them; two classes of one company are two unrelated instruments here. |
| **Volume quality** | Consolidated where it exists, absent where it does not, and never comparable across venues. |

Every one of these is a reason the answer to "what did this strategy return" is
**not available from this data**. What *is* available is whether the pipeline
computes what it claims to compute, which is the only thing worth knowing
before real data arrives.
